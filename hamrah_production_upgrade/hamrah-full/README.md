# پیام‌رسان همراه — نسخه چندکاربره

این پروژه یک **پایه قابل اجرا برای پیام‌رسان واقعی** است؛ رابط فارسی، سرور Node.js، پایگاه داده SQLite و ارتباط زنده Socket.IO دارد.

## اجرا در ویندوز 11

1. Node.js نسخه 20 یا جدیدتر را نصب کنید: https://nodejs.org
2. این پوشه را از حالت ZIP خارج کنید.
3. در همان پوشه CMD یا PowerShell را باز کنید.
4. اجرا کنید:

```bash
npm install
```

5. فایل `.env.example` را به `.env` تغییر نام دهید.
6. در `.env` مقدار `JWT_SECRET` را به یک رشته تصادفی طولانی تغییر دهید.
7. برای تست محلی `OTP_DEV_MODE=true` باقی بماند.
8. اجرا:

```bash
npm start
```

9. مرورگر را باز کنید: http://localhost:3000

در حالت آزمایشی کد یکبارمصرف در ترمینال نمایش داده می‌شود و در صفحه هم نشان داده می‌شود. این فقط برای توسعه محلی است.

## ورود واقعی با پیامک

در `server.js` تابع `sendOtp(phone, code)` محل اتصال به پنل پیامکی است. باید API رسمی سرویس پیامک انتخابی خود را آنجا پیاده‌سازی کنید. سپس `OTP_DEV_MODE=false` قرار دهید. کد پیامک را در پاسخ API یا لاگ عمومی قرار ندهید.

## امکانات موجود در این MVP

- ورود با شماره و OTP (در حالت توسعه، کد آزمایشی)
- حساب کاربری و نشست‌های فعال؛ خروج از نشست
- پیام‌رسانی بلادرنگ با Socket.IO
- ساخت گروه، کانال عمومی و خصوصی
- ارسال فایل با سقف پیش‌فرض ۱۰۰ مگابایت
- عکس، ویدئو، صوت و فایل
- پاسخ به پیام، فوروارد و حذف پیام
- اعلان مرورگر برای پیام جدید
- تماس صوتی/تصویری WebRTC با سیگنالینگ
- نقش مدیر، فهرست کاربران و API مدیریت کاربران
- SQLite و ذخیره پایدار روی دیسک

## پنل مدیریت

برای مدیر کردن شماره، آن را در `ADMIN_PHONES` در `.env` وارد کنید؛ سپس با آن شماره یک‌بار وارد شوید. APIهای مدیریت در مسیرهای `/api/admin/...` هستند. برای رابط کامل پنل مدیریت، می‌توان صفحه مدیریتی جداگانه اضافه کرد.

## نکات ضروری پیش از انتشار عمومی

این پروژه یک MVP آموزشی/قابل توسعه است، نه جایگزین آماده تولید برای ایتا. پیش از استفاده عمومی:
- HTTPS اجباری و دامنه معتبر راه‌اندازی کنید.
- OTP را به پنل پیامکی واقعی وصل کنید و محدودیت نرخ/ضدتقلب اضافه کنید.
- برای تماس از TURN server معتبر استفاده کنید؛ STUN تنها برای همه شبکه‌ها کافی نیست.
- فایل‌ها را در فضای ذخیره‌سازی خصوصی نگهداری و دانلود را با مجوز عضویت کنترل کنید؛ در نسخه فعلی مسیر فایل‌ها عمومی است و باید پیش از انتشار اصلاح شود.
- برای مقیاس بالا از PostgreSQL، Redis، صف پردازش و ذخیره‌سازی object استفاده کنید.
- گزارش ممیزی، بازیابی حساب، مسدودسازی، گزارش تخلف، پشتیبان‌گیری، رمزنگاری انتقال و سیاست نگهداری داده اضافه کنید.
- کلیدهای محرمانه را فقط در متغیرهای محیطی قرار دهید.
- GIF و استیکر فعلاً از طریق بارگذاری فایل GIF قابل استفاده‌اند؛ جستجوی آنلاین GIF نیازمند انتخاب سرویس و API Key است.
- تماس گروهی، رمزنگاری سرتاسری و تماس پایدار در شبکه‌های محدود هنوز پیاده‌سازی نشده‌اند.

## معماری

- `server.js`: API، احراز هویت، SQLite، Socket.IO، بارگذاری فایل و سیگنالینگ تماس
- `public/index.html`: رابط کاربری
- `public/style.css`: ظاهر و واکنش‌گرایی
- `public/app.js`: کلاینت، پیام‌رسانی و WebRTC


## آماده‌سازی انتشار عمومی (HTTPS، فایل خصوصی، TURN و GIF)

### HTTPS و دامنه با Caddy
1. یک VPS لینوکس تهیه کنید و دامنه را با رکورد A به IP سرور وصل کنید.
2. پورت‌های 80 و 443 را در فایروال باز کنید.
3. `.env.example` را به `.env` کپی کنید؛ `DOMAIN` را نیز در محیط اجرا تنظیم کنید.
4. مقدار `APP_ORIGIN` را برابر `https://your-domain` بگذارید.
5. `JWT_SECRET` را با یک مقدار تصادفی طولانی جایگزین کنید.
6. اجرا: `docker compose up -d --build`
Caddy گواهی TLS را خودکار می‌گیرد و تمدید می‌کند.

### فایل‌ها
فایل‌های آپلودشده دیگر از مسیر عمومی سرو نمی‌شوند. دانلود از `/api/files/...` نیازمند ورود است و فقط اعضای گفتگویی که فایل در آن ارسال شده اجازه دریافت دارند. قبل از انتشار عمومی همچنان اسکن بدافزار، محدودیت نوع فایل، فضای ذخیره‌سازی خصوصی/بکاپ و پاک‌سازی فایل‌های یتیم را اضافه کنید.

### تماس پایدار با TURN
یک سرور Coturn جداگانه یا سرویس TURN مدیریت‌شده تهیه کنید. آدرس‌ها را در `TURN_URLS` و secret مشترک REST را در `TURN_SHARED_SECRET` قرار دهید. سرور برای هر کاربر اعتبارنامه کوتاه‌عمر تولید می‌کند. پورت‌های TURN و بازه پورت relay باید طبق پیکربندی Coturn در فایروال باز باشند. بدون TURN، بعضی کاربران پشت NAT یا شبکه‌های محدود تماس موفق نخواهند داشت.

### GIF و استیکر آنلاین
یک API key از Giphy Developers دریافت کنید و در `GIPHY_API_KEY` قرار دهید. سپس دکمه GIF داخل گفتگو امکان جستجوی GIF و استیکر را فراهم می‌کند. برای استفاده عمومی، شرایط مجوز و سیاست محتوای سرویس را رعایت کنید.

### اتصال پیامک واقعی
درگاه پیامکی هنوز به انتخاب شما وابسته است. `sendOtp()` در `server.js` محل اتصال است و باید مطابق API و الگوی تأیید پنل پیامکی شما تکمیل شود. تا آن زمان `OTP_DEV_MODE=false` باعث می‌شود درخواست کد به‌صورت امن fail شود و کد آزمایشی به کاربر نشان داده نشود. کلید API را فقط در `.env` بگذارید.

**مهم:** قبل از انتشار عمومی، تست امنیتی، محدودیت نرخ برای تمام مسیرهای حساس، پشتیبان‌گیری و مانیتورینگ سرور ضروری است. این پروژه هنوز رمزنگاری سرتاسری (E2EE)، تماس گروهی و اسکن فایل ندارد.
